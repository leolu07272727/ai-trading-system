## 0. 屍檢:V1 為什麼沒有 edge(這決定 V2 的每一個設計)

V1 的隱含假設是「用免費公開資料 + 技術過濾,能在日內找到別人沒看到的東西」。
回測與實盤都證明這個假設錯了,而且錯得很結構性:

| V1 的設計 | 為什麼註定沒 edge |
|---|---|
| 日內突破進場 (I2) | 跟全世界的量化基金比毫秒,他們有 co-location,你有 cron |
| 掃公開新聞找催化劑 | 新聞見報 = 已 priced in(實驗 A 首跑抓到 Cramer 電視股就是證據) |
| 技術過濾 (D1/D2) | 免費資料人人有,規則人人寫得出來,擁擠的訊號=沒有訊號 |
| 每天強制平倉 | 把唯一可能有的慢速 edge(持有期)也砍掉了 |

**但 V1 期間發生了一件真的有 edge 形狀的事:MU ~993 進場。** 那筆不是 bot 做的,
是 Leo 的 thesis(「AI 記憶體需求被結構性低估,Street 反應慢」)——事前有理由、
事後被驗證、而且可否證。一次樣本不證明 skill,但它指出了正確的頻率:
**edge 活在「月級的認知落差」,不在「分鐘級的價格行為」。**

→ V2 的全部設計就一句話:**把系統的頻率對齊 edge 的頻率。**

---

## 1. 核心哲學(三條,違反任何一條就是走回 V1 老路)

1. **系統不產生 edge,只執行與檢驗人的 thesis。**
   機器做不到「比市場早想通一件事」,但機器可以:不眠不休地監控 thesis 的
   正反證據、在人想凹單的時候執行事前寫好的規則、記錄每個決策供事後對答案。
2. **每個 thesis 必須事前可否證。** 進場前就寫下「什麼會證明我錯」。
   寫不出否證條件的想法(例如「AI 永遠缺記憶體」)是信仰,不准進系統。
3. **機器的首要任務是餵反方證據。** 人的預設故障模式是確認偏誤;
   系統每天的輸出必須包含「今天出現了哪些對你不利的證據」,而不是幫你找買的理由。
   (2026-07-02 的實例:MU 內部人 90 天 0 買/$139M 賣——thesis 說被低估,
   內部人卻沒人買。這種資訊就是系統存在的意義。)

## 2. 架構:三個引擎,嚴格分離

```
┌────────────────────────────────────────────────────────┐
│  Conviction Engine(人)                                  │
│  產出: theses.yaml — 陳述、否證條件、進出場規則、size    │
└──────────────┬─────────────────────────────────────────┘
               │ thesis(靜態,只有人能改)
┌──────────────▼─────────────────────────────────────────┐
│  Evidence Engine(機器,每日)                             │
│  估計上修 drift / 內部人 Form 4 / AI 新聞共識 / 循環數據 │
│  / 擁擠度 → 每檔吐 EARLY/MID/LATE + 反方證據清單         │
└──────────────┬─────────────────────────────────────────┘
               │ state + evidence(每日快照,jsonl)
┌──────────────▼─────────────────────────────────────────┐
│  Execution Engine(機器,低頻)                            │
│  每天一個決策窗;只在「thesis 狀態轉換」時動作            │
│  IBKR paper;風控 rails;決策全記 ex-ante 理由            │
└────────────────────────────────────────────────────────┘
```

### 2.1 Conviction Engine — `theses.yaml`(人寫,機器只讀)

每個 thesis 一個條目,欄位全部必填,缺一個就不准啟用:

```yaml
- id: ai-memory-2026
  statement: "AI 記憶體(HBM/DRAM)需求被結構性低估,賣方反應慢半拍"
  tickers: [MU, WDC, STX]          # 施力點(NVDA 已驗證是最爛施力點,全市場盯著)
  falsifiers:                       # 任一成立 → thesis 死亡,強制全出
    - "DRAM/HBM 現貨價趨勢翻 down(循環見頂,優先於一切)"
    - "+1y EPS 估計 90 天上修動能歸零或翻負"
    - "hyperscaler capex 指引集體下修"
  entry: "state==EARLY 且價格未貼 52 週高(距高 >10%)"
  add:   "state==EARLY/MID 且回檔 >15% 且無 falsifier 接近觸發"
  trim:  "state==MID 且距 52 週高 <5%(共識追上+貼高=edge 吃完一半)"
  exit:  "state==LATE 或任一 falsifier 觸發"
  max_weight: 0.25                  # 單 thesis 上限(帳戶淨值比)
  review_by: 2026-12-31             # 到期強制人工重審,不准無限展期
  status: active                    # active / paused / falsified / expired
```

**設計重點:**
- 進出場規則綁的是「thesis 狀態」,不是價格形態。停損不是 -8%,是「我錯了的證據出現」。
  (價格停損保留,但只當災難保險,設很寬,例如 -25%——它防的是黑天鵝,不是判斷錯誤。)
- `review_by` 強制到期:cyclical 的 thesis 沒有永久有效這回事,防 permabull 化。
- 機器永遠不寫這個檔。新 thesis 只能由人加,這是「edge 來自人」的落實。
- **已知取捨(刻意的,不是漏洞)**:entry 要求「距高 >10%」會錯過一路創高不回頭的贏家。
  接受——這個系統的假想敵是「追高買在頂」,不是「少賺一段」;MU 993 那種
  「大家不信、股價被壓著」的進場點才是 thesis 型 edge 的原型。錯過強勢股的成本
  由 add 規則(回檔 >15% 補)部分回收,不另開追高例外。

### 2.2 Evidence Engine — thesis_monitor 的直接演進(80% 已存在)

現有的 `thesis_monitor/` 就是這一層的雛形,V2 只是把它從「儀表板」升格為「決策輸入」:

| 訊號 | 來源 | 已存在? | 角色 |
|---|---|---|---|
| 估計上修 drift(90/7天) | yfinance eps_trend | ✅ monitor.py | 核心:「Street 追上沒」 |
| 分析師擁擠度 | yfinance 評等+目標價 | ✅ monitor.py | crowding 偵測 |
| 內部人 Form 4 | SEC EDGAR | ✅ insider_scan.py | 測謊機(反方證據優先) |
| AI 新聞共識 drift | Finnhub + Claude | ✅ news_scan.py | 規則判讀的平行對照 |
| 循環領先指標 | 手動 cycle_data.json | ✅ | 頂部訊號,優先權最高 |
| 動能/位置(RSI、距高) | yfinance | ✅ monitor.py | froth 偵測 |

新增的只有兩件事:
1. **輸出機器可讀**:每日每檔吐 `{state, evidence_for[], evidence_against[], falsifier_proximity{}}`
   進 jsonl(現在已經有 history/,補齊結構化欄位即可)。
2. **falsifier_proximity**:對照 theses.yaml 的否證條件逐條評估「還差多遠」,
   例如現貨價 up→flat 就要開始告警,不等翻 down 才叫。
3. **資料健康檢查(自查時發現的洞,必補)**:
   - `cycle_data.json` **超過 14 天未更新 → 每日告警,且循環訊號視為失效、失效期間
     禁止新進場**。最高優先權的訊號不能默默過期——寫這條的當天它已經 6 天沒更新了。
   - yfinance `eps_trend` 是核心訊號卻是**單一來源的非官方爬蟲**:連 3 日抓不到 →
     告警;數值單日跳動 >50% → 標記可疑、當日不觸發狀態轉換(髒資料比沒資料更危險)。

AI(判官)在這一層與 Execution 的角色轉換,見 §2.4——原則先講:AI 判讀永遠
不改變規則判定,只平行記錄。規則是對照組,AI 是實驗組,分歧本身就是資訊。

### 2.3 Execution Engine — 低頻、無聊、可審計

- **決策窗一天一次**(盤前),不做任何盤中決策。日內波動與這個系統無關。
- **只在狀態轉換時動作**:EARLY→進、MID 貼高→減、LATE/falsified→出。
  沒有轉換的日子,正確行為是什麼都不做。預期一年動作次數:**個位數到十幾次**。
- **狀態轉換要阻尼,否則邊界股會來回打臉**(實例:MU 在「距高 -12%」門檻邊緣,
  6/26 讀 MID、7/2 讀 EARLY——沒有阻尼就是 trim→re-enter 的 churn 機器):
  - 轉換須**連續 3 個交易日**同讀數才成立,單日翻轉一律當雜訊;
  - 任何動作後 **10 個交易日冷卻期**,期間不做反向動作;
  - 唯一例外:**falsifier 觸發的出場即時執行**,不等確認——逃生門不裝阻尼。
- **人機權責不對稱(防凹單的核心設計,方向寫死)**:
  - **進場/加碼 = 機器提案,人 24h 內 ack 才執行**(魔鬼代言人的反方陳詞附在提案裡);
    人不 ack = 不做,錯過就錯過。
  - **減碼/出場 = 機器自動執行,人不可否決**。要推翻只能事後改 `theses.yaml`
    並留下紀錄(這個紀錄本身就是凹單證據,直接觸發 §4 第 4 條)。
  - 一句話:**想冒險要過人這關,想逃跑機器不等人。** 凹單在架構上被做掉,不靠自制力。
- **每筆單進場前先寫 log 再下單**:`{ts, thesis_id, action, ex_ante_reason,
  evidence_snapshot, expected_falsifiers}`——事後對答案的原料,V1 的 decision_log
  慣例直接繼承。
- **風控 rails(從 V1 原封搬過來,這部分 V1 做對了)**:
  - `PAPER_TRADING=true` 直到通過 §5 門檻;risk 區塊只准往保守調
  - 單 thesis ≤25%、單票 ≤15%、總曝險 ≤80%,現金是合法倉位
  - 財報 blackout 保留(進場端;已持有者財報前重審而非自動平)
  - 停損單 GTC 孤兒問題、permId 比對、formed-bar 排除——V1 踩過的坑全部寫進實作 checklist
- **明確刪掉的 V1 部件**:D1/D2/I2 掃描、盤中 cycle、15:51 force_close(改為「只在
  falsifier 觸發時平倉」)、每日候選池、判官的進場 clamp(沒有日內進場就沒有東西可 clamp)。

### 2.4 AI 判官 — 職位轉換(V1 守門員 → V2 反方陳詞人)

V1 判官的工作是「盤中進場候選出現時,讀新聞決定放行/砍倉位」。V2 沒有盤中進場,
這個崗位隨 I2 一起裁撤——**不是能力被否定,是它守的那扇門被拆了**。
能力(LLM 讀非結構化文本 + tool call 吐結構化判斷)在 V2 有三個新職位:

| 職位 | 判的問題 | 掛在哪 | 狀態 |
|---|---|---|---|
| ① 共識判讀員 | 「Street 追上沒?共識往哪飄?」 | Evidence Engine,每日 | ✅ 已上任(實驗 B `news_scan`) |
| ② 魔鬼代言人 | 「這個動作錯的最強理由是什麼?」 | Execution,狀態轉換時 | V2 新增,最高價值 |
| ③ falsifier 語意監控 | 「否證條件在財報措辭裡出現了嗎?」 | Evidence Engine,財報季 | V2 新增 |

**① 共識判讀員**:判官轉世。同一套技術(Claude + 強制 tool call + SECURITY 段落),
判的問題從「這筆單能不能進」換成「共識溫度」。這個換位就是 V1 最重要的教訓之一:
新聞當**進場訊號**沒 edge(見報=priced in,已驗證),但當**共識溫度計**有效——
因為 thesis 的整個賭注就是「共識落後於現實」,共識飄到哪正是要測的變數。

**② 魔鬼代言人**:Evidence Engine 觸發狀態轉換、Execution 準備動作之前,
AI 必跑一次反方陳詞——拿當天全部證據(含 evidence_against、insider、crowding)
寫出「你這個動作錯的最強論證」,與 ex-ante log 一起落盤。**不擋單、不改判定**,
但動作執行前人必須看過反方論點(Telegram 推送,含在轉換告警裡)。
這是把判官從守門員改成陪審團裡專職唱反調的人,直接落實 §1 第 3 條(機器餵反方證據)。
防的失敗模式:確認偏誤 + 凹單(falsifier 接近時,反方陳詞會越來越難看,形成心理壓力梯度)。

**③ falsifier 語意監控**:`theses.yaml` 的否證條件分兩種——規則抓得到的
(現貨價翻 down、估計動能歸零)和只有語意抓得到的(「hyperscaler capex 指引轉保守」
藏在財報電話會措辭裡、「三雄擴產紀律鬆動」藏在法說問答裡)。後者規則寫不出來,
是 LLM 的獨占領域。財報季逐條掃 falsifiers,吐 `falsifier_proximity` 的語意分量。

**鐵律(從 V1 繼承,不可逆的順序):**
1. **AI 永遠沒有最終決定權。** V1 判官只能 clamp 不能加碼;V2 判官連 clamp 都沒有,
   純平行記錄。規則判定是對照組,AI 是實驗組,兩者分歧本身就是資料(進 §3 的 A/B)。
2. **升權先過數據關**:跑 ≥6 個月 A/B,AI 判讀顯著優於純規則,才討論給投票權
   (例如「AI 反方陳詞出現 X 情況時延遲執行 24h」)。順序不能反:先有權再驗證=V1 前車。
3. **SECURITY 段落不許刪**:新聞/財報文本=不可信輸入,嵌入指令一律不從。原樣繼承。
4. **降級路徑**:AI 掛掉/沒 key/超時 → 系統照常用純規則跑,只是少一行 AI 判讀
   (V1 `fallback_rule_only` 慣例)。AI 是增強,不是依賴。

## 3. 實驗框架:每個決策都是一筆樣本

V1 最有價值的遺產不是策略,是「決策漏斗可觀測」的習慣。V2 把它從 debug 工具升格為系統目的:

- **ex-ante 對 ex-post**:每筆動作 90 天後自動回顧——當初的理由兌現了嗎?
  是 thesis 對了,還是運氣?(方向對但理由錯 = 運氣,誠實記錄)
- **對照組永遠在跑**:同期 SPY buy-and-hold + 「進場後死抱不動」兩條 benchmark。
  V2 要贏的不是零,是「什麼都不做」。
- **樣本門檻**:<10 筆完整的進出循環不下任何結論(V1 是 30 筆日內樣本,
  V2 頻率低所以循環數少、但每筆資訊量大)。
- **AI vs 規則的分歧記錄**:news_scan 與規則判定不一致的日子單獨記錄,
  年底回看誰對得多——這決定 AI 判讀要不要升權重。

## 4. 通往真錢的門檻(Promotion Gates)

寫死在這裡,防止未來的 Leo(或未來的 AI)被 paper 綠字沖昏頭:

1. **Thesis 級**:同一個人(Leo)事前寫下的 thesis,完整走完進出循環且方向正確 **≥3 次**,
   其中至少 1 次是「出場判斷正確」(會買只是一半的技能,會走才是全部)。
   **誠實換算:以 V2 的頻率,3 個完整循環是 2-4 年,不是 2-4 個月。
   走得慢是這個門檻的目的,不是缺陷——嫌慢的解法是回去買指數,不是調低門檻。**
2. **帳戶級**:paper 跑 **≥6 個月且累積 ≥2 個完整進出循環**(兩者都要;只有時間沒有
   循環數=樣本不足,見 §3),風險調整後(比 Sharpe 或最大回撤)不輸 SPY。
   單看 6 個月的集中持股贏輸 SPY,大半是 beta 加運氣,所以循環數是硬條件。
3. **就算全過**:真錢帳戶 cap 在「全損不影響生活」的金額,主資金仍是指數
   (V1 結案結論,繼承,不重談)。
4. **任何一個 falsifier 觸發後凹單一次** = 直接取消真錢資格,回 paper 重新計數。
   系統存在的意義就是防這個,凹單代表系統失效。

## 5. 已知失敗模式與內建解藥

| 失敗模式 | V2 的解藥 |
|---|---|
| 確認偏誤(只看利多) | Evidence Engine 每日輸出必含 evidence_against;內部人零買入這類資訊置頂 |
| Permabull 化(「永遠缺貨」) | falsifiers 必填 + review_by 強制到期 |
| Cyclical 頂部(低 P/E 陷阱) | 現貨價趨勢優先權最高,翻 down 直接 override 估計動能 |
| Crowding(對但太晚) | MID 貼高強制 trim,規則寫死不留裁量 |
| 頻率漂移(手癢想做日內) | Execution 一天一個決策窗,架構上做不了日內,不是靠自制力 |
| AI 幻覺/新聞投毒 | AI 只平行顯示不改判定;SECURITY prompt(新聞=不可信輸入)慣例繼承 |
| 配置漂移(V1 的 50 倉事故) | 風控唯一來源一個檔案;啟動時 print 生效配置進 log |

## 6. 落地路徑(不拆現有系統,平行跑)

現有 paper bot 已定位為「監控練習」,留著,不動。V2 平行長出來:

- **Phase 1(一個週末)**:寫 `theses.yaml`(第一條就是 ai-memory-2026);
  thesis_monitor 補結構化輸出 + falsifier_proximity。不碰執行,人肉照著訊號走,
  但每個決策開始記 ex-ante log。→ **這一步完成後系統已有 80% 價值。**
  含**期初對帳**:MU 既有持倉(993 進場)以「已進場」狀態接入,補記一筆 retro 基準 log
  (標記 `retro`,**不計入 §4 的循環次數**——那筆是 thesis 的起源故事,不是系統的成績;
  系統只對「接手之後」的管理與出場負責並計分)。
